# Applying the Suite in Different Hosts

The portable unit is readable Markdown plus the supporting material a task needs. A model must receive the actual bodies to use them. Choose the available loading route and preserve a concise record of selected decisions across long tasks.

| Host capability | Loading and execution |
| --- | --- |
| Native skills and file access | Discover descriptions, read the coordinator for broad work or a specialist for a narrow request, then read conditionally linked references |
| MCP tools | Call visual_engineering_start or visual_engineering_list, then visual_engineering_read for names and visual_engineering_reference for exact reference IDs |
| MCP resources | Read visual-engineering://catalog and the full resource URIs it identifies; references use visual-engineering://references/<skill>/references/<file>.md |
| Text context only | Supply the coordinator, catalog, selected specialists, and selected reference bodies in a context bundle; supply additional bodies when needed |
| Code editing without browser or vision | Complete implementation and executable checks; ask for relevant visual observations when needed and identify unobserved appearance |
| Browser and visual inspection | Inspect matched views and actual interactions; capture playback or sampled sequences for motion questions |

For text context, the package command `node scripts/export.mjs` produces a coordinator/catalog bundle. Repeat `--skill NAME` and `--reference ID` to include task-specific bodies. `--all` is explicit because reading the entire suite can spend context on irrelevant disciplines. A person can also copy the same Markdown directly; the native guidance itself does not need Node.

Named starting selections are `award-ui` for creative concept development (combine with `premium-ui` for delivery foundations), `premium-ui` for complete interface foundations, `interactive-motion` for graphics/cursor/scroll/media, `luxury-cinematic` for editorial cinematic work, and `product-3d` for scene construction and assembly. Retrieve one with `visual_engineering_bundle`, its catalog resource URI, or `node scripts/export.mjs --bundle NAME`. Repeated `--bundle` flags in one export deduplicate shared bodies. Bundle descriptions identify their scope; a linked reference outside that selection remains unloaded until supplied.

For a smaller context window, load in stages: direction/composition to resolve the brief; selected runtime/media references to implement; relevant responsive/accessibility/QA bodies to finish and verify. Carry the actual chosen tokens, dimensions, hierarchy, input modes, motion endpoints, budgets and evidence limits between stages. Do not replace these values with a vague summary such as “make it premium.” Ask for missing bodies only when a consequential decision needs them, and continue independent work with available guidance. File portability does not imply that every host has enough context or tools for every bundle.

Expose this activation instruction through the host's supported mechanism:

> For substantial visual design or implementation, load visual-engineering-intelligence and then the selected specialists and relevant references. For a narrow repair, load its owning specialist. Apply the decisions to the requested artifact, inspect available evidence, and complete the authorized work. A link does not load a document.

Tool names in this package identify its MCP retrieval functions. The instructions do not assume a vendor-specific editor, renderer, model setting, or hidden memory. Use the host's available tools for execution. Missing image inspection, graphics hardware, assets, permissions, or model capacity cannot be supplied by wording in a skill.

Use one canonical package copy. Native Markdown and MCP text provide the same guidance; MCP rewrites local links to resource addresses and adds retrieval instructions. Loading both bodies wastes context. When changing packaged documents, restart MCP to replace its startup snapshot.
